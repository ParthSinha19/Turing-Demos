# ML benchmark results

Generated by `npm run bench` using the deterministic synthetic scenarios in `src/ml/benchmark.ts`. The figures below are recorded from the current implementation; they are not estimates or hard-coded output.

| Scenario | Decision tree | Nearest neighbour | What it illustrates |
|---|---:|---:|---|
| Clearly separable categories (16 train / 8 test) | 8/8 (100%) | 8/8 (100%) | Both methods learn the obvious distinction in this setup. |
| Sparse examples (2 train / 3 test) | 3/3 (100%) | 3/3 (100%) | A tiny, simple test can look deceptively easy; it does not establish robustness. |
| Near-identical lookalikes (pattern is the only class signal) | 2/2 (100%) | 2/2 (100%) | Both methods can use one informative feature when the examples support it. |
| Conflicting labels (identical features, opposite labels) | 1/1 (100%) | 1/1 (100%) | The single test item happens to match the deterministic tie outcome. This is **not** evidence that the contradiction was resolved; tree evidence reports no useful split and kNN explicitly reports mixed labels. |
| Class imbalance (18:2 train, 4:4 test) | 8/8 (100%) | 4/8 (50%) | Neighbour voting can favour the majority class in this particular arrangement. |
| Unseen feature combinations (crossed feature combinations) | 2/2 (100%) | 0/2 (0%) | The tree generalises by its learned feature split here; nearest neighbours remain close to examples with the opposite combination. |
| Irrelevant-feature variation | 2/2 (100%) | 2/2 (100%) | Both handle these two held-out cases; two cases are far too few for a general robustness claim. |

## Interpretation and limitations

- These are deliberately small, synthetic teaching scenarios. Percentages are descriptive of each listed test set only.
- The conflicting-label scenario has only one test item; a nominally correct answer does not mean the model can infer an unobservable distinction.
- The unseen-combination result depends on the exact constructed examples and the decision-tree tie/split policy. It is not a universal result for decision trees versus nearest neighbours.
- The initial production UI offers both classifiers so learners can compare them. The project does not claim that either classifier is best for every dataset.
- A future research-quality benchmark should repeat each scenario over multiple seeds, vary noise and sample size, report variability, and test across browsers/devices. These results are a transparent prototype benchmark, not a publication-grade empirical study.
